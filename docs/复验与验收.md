# 项目复验与验收记录

本轮由主模型直接复验和修改，保留工作区原有未提交内容；复验当时未提交、推送、安装、签发或发布 APK。这批改动随后连同复验结论提交为 `0.29.0 / 53` 并正式发布，证据见文末「v0.29.0 发布记录」。

## 复验后补齐的修改

| 问题 | 本轮处理与证据 |
|---|---|
| 现有源码无法编译 | 修正 `Actions.RunResult` 遗留引用及 Java 测试调用；离线编译将 Java 与 Kotlin 输出分离，避免嵌套 Java 类型解析冲突。 |
| 取消掩盖松手失败 | `ActionFailure` 先检查完整异常链中的释放失败；`Actions` 统一处理取消和普通异常，危险结果锁住后续注入。 |
| 进程收尾结果丢失 | 提取 `TouchProcess`，无论正常、非零退出、取消还是强杀，都在收尾后检查回执。`TouchAgent` 增加 `TOUCH_IDLE`；DOWN 结果不确定时也不声称触摸已释放。 |
| 跳跃组合异常 | 跳跃 MOVE 和 UP 同时失败的生产路径回归已加入测试入口，不能再按可忽略的跳跃失败处理。 |
| 走位协议和预算错误 | 修正跳跃参数顺序；无跳跃预算为 `4D+500ms`，有跳跃为 `4D+1500ms+跳跃按压`。测试对照生产动作时钟，而非只重复预算公式。 |
| 跳跃坐标屏幕记录遗漏 | 本轮使用跳跃点时，与轮盘一起校验屏幕记录。让路矩形右下边界包含屏幕最后一个像素。 |
| 更新下载无资源上限 | 最多 64 MiB、120 秒总时限检查、至多 5 次 HTTPS 跳转；拒绝截断响应并删除半包。使用可控响应测试，不联网。 |
| 更新兼容性预检不足 | 仅接受既有唯一正式签名，并与当前安装签名比较；未开放密钥轮换。发布清单与应用内信任锚必须一致。 |
| 标定服务边界不完整 | 页面路由仅开放 `index.html`，截图限制在目录内；拒绝路径穿越、符号链接逃逸、跨站保存和非 JSON 保存请求。测试覆盖 GET、HEAD 和 POST。 |
| 发布可能误报通过 | 增加只读 APK 校验脚本，核对包名、版本、签名和摘要；远端包必须与本地验证产物逐字节一致，来源验证失败不得被 printf 吞掉。 |

已存在且本轮保留的修改包括：签名配置外置、标注取消回调及辅助功能取消入口、HTTPS-only 策略、部分屏幕安全边界处理、回归测试入口补全。源码检查不能替代对应设备行为验收。

## 验证命令

```bash
python3 tools/verify.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/calibrate -p 'test_*.py' -v
bash -n tools/release.sh tools/build.sh tools/setup-toolchain.sh
git diff --check
python3 tools/verify-artifact.py dist/probe-release.apk
```

前四项用于离线源码、回归、资源和脚本检查。第五项预期拒绝当时的历史镜像：`dist/probe-release.apk` 为 `0.28.5 / 51`，当时源码为 `0.28.6 / 52`。复验当时源码确实还没有可分发 APK；本次发布后的镜像校验结果见文末「v0.29.0 发布记录」。

Gradle 命令为：

```bash
source .toolchain/env.sh
./gradlew :probe:automationRegression :probe:lintDebug :probe:assembleDebug --no-daemon --console=plain
```

该命令已于同日**实际执行并通过**（输出 `BUILD SUCCESSFUL`，42 个任务，其中 `automationRegression`
打印的 PASS 行包含失败分类/注入闸门/走位预算/子进程回执/更新下载等全部用例）。执行前修掉了它暴露的
4 个 `NewApi` lint 错误：`OverlayService.screenBounds()` 读取 `Insets` 字段的地方必须在

`class file version >= 56` 的支持性警告，属工具版本提示，需要时在完整构建与设备上继续核实。

## 独立复核

本轮改动另由只读 Reviewer 复核（不修改文件），结论为 `CHANGES_REQUIRED`，**无 blocking**：7 条验收标准的实现链路未发现可绕过漏洞，
并独立复跑了上面的 Gradle、`verify.py`、标定单测与脚本检查。它指出 4 条准确度/文档问题，均已在本轮修掉：

| 复核意见 | 处理 |
|---|---|
| 闸门拦截曾被标成"触摸状态未知"，日志会指向错误原因 | `RunResult.isDangerous()` 改为 `!blocked && isReleaseUnknown()`，回归断言同步要求"被挡住 ≠ 触摸状态未知" |
| 目标包名分支可能覆盖同一轮的走位冲突提示 | `syncExternalSettings` 合并为单次提示判定，冲突提示不再被通用文案重置 |
| `versionName/versionCode` 有写死回退值，版本文件丢失会静默沿用旧版本 | 移除回退：`version.properties` 或字段缺失即构建失败 |
| 文档未记录草稿冲突机制、默认构建在缺凭证时失败、1280×720 基线 | 补进 [软件整体架构](软件整体架构.md)、[版本更新与发布](版本更新与发布.md)、[主要功能](主要功能.md) |

Reviewer 同时列出未覆盖项：子进程已退出但输出尚未排空时 `TouchProcess` 可能误判为"未确认松手"（fail-closed 但会误锁）。
本轮已增加一次有界排空等待以降低误报概率，真实误报率仍需实机观察。
