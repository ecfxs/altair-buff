## 1. 为什么重构

### 1.1 现状

监控台当前**不是网页项目**，而是 `tools/control-server.py` 里的一个字符串：

| 项 | 实测 |
|---|---|
| `PANEL_HTML` | 第 83–427 行，**344 行 / 17KB**，HTML+CSS+JS 全内联 |
| 注入方式 | `_panel()` 替换 `__TOKEN__` / `__USER__` / `__ICO_LOG__` 三个占位符 |
| 质量保障 | 仅 `tools/check-assets.sh`：正则抠 `<script>` → `node --check` → 手写 DOM 桩跑 `refresh()` |
| 第二套手写页 | `tools/calibrate/index.html`（313 行）+ `tools/calibrate/server.py`，样式同源但代码完全独立 |
| 服务端 | Python 3 标准库 + `control-store.json`（整文件读写，无历史、无审计） |
| 部署 | 单 `.py` → GitHub raw → systemd（"零依赖单文件"曾是卖点） |

**重构的根本理由**：为了维护这段内嵌 HTML，我们已经自己写了一套 JS 检查器和 DOM 桩。
这不是可持续的形态 —— 每加一个功能（历史曲线、截图画廊、批量操作、配置版本）都要在这套自制工具链上继续加码。

### 1.2 本次范围（已确认的跳变）

不是"把页面抽出来"，而是：

> **用 Go 重写整个集控服务端 + 用 React 重写前端，设备协议一并升级到 v1，Python 彻底下线。**

附带收益：换成 Go 单二进制后，"零依赖单文件"的卖点**更强** —— VPS 上不需要 Python/Node/Nginx 任何运行时。

## 3. 架构

```
   云手机 APK ──HTTPS──┐
                       │   ┌─────────────── VPS ───────────────┐
                       ├──▶│ Caddy（自动 Let's Encrypt 证书）   │
   浏览器 ─────HTTPS───┘   │   control.example.com              │
                           │     ├─ /*        → 127.0.0.1:8788  │
                           │     └─ /api/v1/* → 127.0.0.1:8788  │
                           │                        │           │
                           │              ┌─────────▼─────────┐ │
                           │              │  altaird（二进制） │ │
                           │              │  ├ go:embed SPA    │ │
                           │              │  ├ 设备 API        │ │
                           │              │  ├ 面板 API + SSE  │ │
                           │              │  └ SQLite (WAL)    │ │
                           │              └───────────────────┘ │
                           └────────────────────────────────────┘
                                        /var/lib/altair/
                                        ├ altair.db
                                        └ shots/<deviceId>/*.jpg

   本机开发： altaird --addr 127.0.0.1:8788  +  pnpm -C control/web dev（proxy /api → 8788）
   标定页：   altaird calibrate --root .     （本地专用，读写 shots/）
```

### 3.1 架构约束（**不受重构影响**，别试图绕）

云手机在机房 NAT 后面，**没有公网 IP，服务器无法主动连它**。所以：

- 设备只能**主动上报 / 主动拉取**，`desired` 期望状态 + `rev` 去重的模型必须保留。
- SSE 是**浏览器 → 服务器**方向的连接，不违反该约束，可以放心用来做实时。
- "合并往返"（D 见 §5.1）只能减少往返次数，不能变出推送。

## 4. 技术选型

| 关注点 | 选择 | 为什么是它 |
|---|---|---|
| Go 版本 | **1.27.1**（已装在 `.toolchain/go`，见 §9.5） | `net/http` 的 `ServeMux` 已支持方法+通配符路由，不需要第三方路由库 |
| SQLite 驱动 | **`modernc.org/sqlite`**（纯 Go） | 无 cgo → `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build` 直出 Linux 二进制，本机 macOS 交叉编译零障碍。**不要用 `mattn/go-sqlite3`**（cgo 会拖入交叉编译工具链，破坏单二进制卖点） |
| 路由 | 标准库 `net/http` | 路由需求很浅（约 25 个端点），少一个依赖 |
| 契约 | **`control/api/openapi.yaml` 为唯一来源** → `oapi-codegen`（Go 端接口与类型）+ `openapi-typescript`（前端类型） | 两个语言之间靠**生成**同步，不靠记性；CI 跑 codegen 后 `git diff --exit-code` 卡住任何漂移 |
| 会话 | 32 字节随机 token，**哈希后入库**；`HttpOnly; Secure; SameSite=Lax; Path=/` Cookie | 数据库支撑 → 可立即吊销、可查看在线会话；比 JWT 更适合单机服务 |
| 口令 | **argon2id**（`golang.org/x/crypto/argon2`），PHC 串存库 | 替掉旧的明文/弱哈希 |
| 日志 | 标准库 `log/slog`（JSON handler） | 结构化，systemd journal 可直接检索 |
| 限流 | 内存令牌桶（按 IP / deviceId）+ `audit` 表记录 | 替掉旧版"认证失败 sleep 1s"的土办法 |
| 迁移 | `embed` 的 `internal/store/migrations/NNNN_*.sql` + `schema_migrations` 表 | 单二进制自升级，不依赖外部迁移工具 |
| 前端构建 | Vite + React + TS + Tailwind v4 | — |
| 前端数据层 | **TanStack Query** | 轮询、缓存、mutation、重试、失效现成；SSE 事件直接 `invalidateQueries` |
| 前端路由 | react-router | 为"总览 / 设备详情 / 配置 / 审计 / 设置 / 标定"多页做准备 |
| 图表 | **待定**（uPlot 或 Chart.js），P2 再定 | 先留数据接口与组件边界，别过早在 P0 引入 |
| 图标 | 内联 SVG 抽成 React 组件 | 沿用现有图标集，零依赖、离线可用 |

## 5. API 契约 v1

契约唯一来源是 `control/api/openapi.yaml`，本节是它的设计说明与字段依据。

### 5.1 设备 API（`/api/v1/device/*`）

**鉴权**：`X-Altair-Token: <deviceToken>`；亦允许 `?token=`（**仅供 curl 排障**，日志中脱敏）。

#### `POST /api/v1/device/report`

请求：

```json
{
  "deviceId": "a1b2c3d4e5f6",
  "protocolVersion": 1,
  "ts": 1699999999999,
  "uptimeMs": 123456,
  "versionCode": 24,
  "versionName": "0.24.0",
  "model": "samsung SM-G9910",
  "android": "13",
  "targetPkg": "com.nexon.mod",
  "foreground": "com.nexon.mod",
  "armed": true,
  "appliedRevision": "r1730000000000",
  "engine": {
    "running": true, "state": "WAITING", "inputMethod": "keyevent",
    "cycleCount": 12, "nextDueAt": 1699999999999, "cyclePeriodMs": 258000,
    "lastResult": "补 BUFF1 成功", "lastError": "",
    "buffs": [{ "idx": 1, "enabled": true, "key": 1, "durationMin": 5 }]
  },
  "heartbeat": { "batteryPct": 87, "charging": true, "thermalC": 38.5, "memFreeMb": 1204, "netRttMs": 42 },
  "logTail": ["…"]
}
```

响应：

```json
{
  "ok": true,
  "ts": 1699999999999,
  "desired": { "running": true, "rev": 7 },
  "configRevision": "r1730000000000",
  "nextReportInMs": 30000,
  "commands": [{ "id": "c_8f3a", "action": "screenshot" }]
}
```

三个关键设计：

1. **合并往返**：响应直接带回 `desired` 与 `configRevision`，设备只在 `appliedRevision != configRevision` 时才去 `GET /device/config`。
   启停延迟从"≤1 个上报周期 + 1 次轮询"降到"≤1 个上报周期"，设备流量减半。
2. **`nextReportInMs` 由服务端下发**：这是"可配上报周期"的实现方式 —— 改周期不需要动配置 `revision`，也不需要重发 APK。设备侧只做 `clamp(报告值, 15s, 5min)`。
3. **`commands` 一次性指令通道**：与 `desired`（持续状态）分离。每条指令有 id，设备执行后在下次 report 里带 `ackedCommands: ["c_8f3a"]`（或调 `/device/ack`），服务端据此标记 `acked_at`，避免重复执行。截图点播走这条通道。

#### `GET /api/v1/device/config?deviceId=xxx`

响应即配置体 + 期望状态，字段沿用现有语义（`revision` / `targetPkg` / `pressMs` / `skillPoints` / `inputMethod` / `buff[]` / `notes`）外加 `desired`，
以及 v0.24 新增的 **`autoFreeMarket`**（回城模式：每轮补完 BUFF 自动进自由市场等待并走到出口待命）。

**只有 `revision` 变化才应用并热重载** —— 这条语义必须保留，否则每轮上报都重写配置、可能打断正在执行的流程。

#### `POST /api/v1/device/screenshot`（multipart/form-data）

- `meta` 字段：JSON `{ "deviceId": "…", "ts": …, "label": "可选" }`
- `file` 字段：`image/jpeg` 或 `image/png`，**上限 2MB**（服务端校验 Content-Length 与实际字节，超限 413）
- 返回 `{ "ok": true, "id": "s_…", "ts": … }`
- 落盘 `/var/lib/altair/shots/<deviceId>/<ts>_<id>.jpg`，元数据入 `screenshots` 表

#### `POST /api/v1/device/ack`

`{ "deviceId": "…", "commandIds": ["c_8f3a"], "result": "ok" | "错误文本" }`

#### `GET /healthz`

免鉴权，返回 `{ "ok": true, "ts": … }`。保留旧行为以便现有探活脚本继续可用。

#### 设备端点限流

`report` 按 `deviceId` 限制最小间隔（默认 5s，超出返回 429 并只记一次审计），防止某台设备配置错误把服务器打爆。

### 5.2 面板 API（`/api/v1/panel/*`）

**鉴权**：会话 Cookie（`login` 除外）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/login` | `{username,password}` → Set-Cookie + `{ok,user,expiresAt}`；失败按 IP+用户指数退避并写审计 |
| POST | `/logout` | 删除会话 |
| GET | `/me` | `{user, deviceToken}` —— **这是替代旧 `__TOKEN__` 注入的正式通道** |
| GET | `/devices` | 设备列表 + 聚合统计（**严格白名单字段，绝不返回任何密钥**） |
| GET | `/devices/{id}` | 详情 + 最近 N 条上报 |
| GET | `/devices/{id}/history?from=&to=&step=` | 时间序列（在线、轮次、心跳）供曲线 |
| GET | `/devices/{id}/logs?limit=200&q=` | 日志检索（从 `logs` 表） |
| PUT | `/devices/{id}/interval` | `{reportIntervalMs}` → 下次 report 的 `nextReportInMs` 生效 |
| POST | `/devices/{id}/command` | `{action:"start"\|"stop"}` → bump `desired.rev` + 审计 |
| POST | `/devices/batch-command` | `{ids:[…],action}` → 批量启停 |
| GET | `/configs/{scope}` | scope = `default` 或 deviceId |
| PUT | `/configs/{scope}` | **revision 由服务端生成**（客户端不许指定），旧版本归档进 `config_revisions`，写审计 |
| GET | `/configs/{scope}/revisions` | 版本列表 |
| POST | `/configs/{scope}/rollback` | `{revision}` → 用历史版本覆盖并生成新 revision |
| GET | `/screenshots?deviceId=&limit=` | 截图列表 |
| GET | `/screenshots/{id}` | 原图（会话鉴权后返回字节流） |
| DELETE | `/screenshots/{id}` | 删图（含磁盘文件）+ 审计 |
| GET | `/audit?limit=&actor=&target=` | 审计日志 |
| GET | `/events` | **SSE**：`event: report\|command\|screenshot\|device-online\|device-offline`，每 20s 注释保活 |

`GET /devices` 响应形状（前端一次拿到渲染总览所需的全部数据）：

```json
{
  "devices": [{
    "id": "a1b2c3d4e5f6", "lastSeen": 1699999999, "firstSeen": 1699000000,
    "online": true, "group": "默认", "tags": [],
    "model": "samsung SM-G9910", "android": "13", "versionName": "0.24.0",
    "protocolVersion": 1, "appliedRevision": "r173", "configRevision": "r173",
    "desired": { "running": true, "rev": 7 },
    "engine": { "state": "WAITING", "cycleCount": 12, "nextDueAt": 1699999999999, "cyclePeriodMs": 258000 },
    "heartbeat": { "batteryPct": 87, "thermalC": 38.5 },
    "foreground": "com.nexon.mod", "armed": true,
    "latestScreenshotId": "s_…",
    "stats": { "cycles24h": 12, "onlineRate24h": 0.98 }
  }],
  "totals": { "total": 2, "online": 2, "running": 1, "cycles": 24 }
}
```

> **安全修复点（D7 的附带项）**：旧的 `GET /api/devices` 直接把整个 store `_json(st)` 返回，
> 其中 `auth.panelPass` 是**明文面板密码**，等于每 5 秒往浏览器送一次。
> 新版 `/devices` 必须是显式白名单结构；`panelPass` 永不出库为明文（只存 argon2id 哈希）。

## 6. 数据模型（SQLite，草案 DDL）

```sql
-- 设备主表
CREATE TABLE devices (
  id                TEXT PRIMARY KEY,
  first_seen        INTEGER NOT NULL,
  last_seen         INTEGER NOT NULL,
  model             TEXT, android TEXT, version_name TEXT,
  protocol_version  INTEGER NOT NULL DEFAULT 1,
  group_name        TEXT NOT NULL DEFAULT '默认',
  tags              TEXT NOT NULL DEFAULT '[]',
  report_interval_ms INTEGER,              -- NULL = 用全局默认
  notes             TEXT,
  created_at        INTEGER NOT NULL,
  updated_at        INTEGER NOT NULL
);

-- 上报时间序列：**只留标量字段**（迁移 0002 起不再存整包 JSON，见 §13.5 的实测）
CREATE TABLE reports (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  device_id    TEXT NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
  ts           INTEGER NOT NULL,           -- 设备时钟
  received_at  INTEGER NOT NULL,           -- 服务器时钟
  foreground   TEXT, armed INTEGER, running INTEGER, state TEXT,
  cycle_count  INTEGER, battery_pct INTEGER, thermal_c REAL, net_rtt_ms INTEGER,
  payload      TEXT NOT NULL DEFAULT ''    -- 保留列以兼容老库，新数据写空串
);
CREATE INDEX reports_device_ts ON reports(device_id, ts DESC);

-- 每台设备「最近一次完整上报」的快照，覆盖写。面板读它重建卡片状态。
-- 与时间序列分开存是容量上的关键决定：完整 JSON 约 820 字节/份，
-- 而同一份内容每 60 秒就会重复一次 —— 只需要留最新的那一份。
CREATE TABLE device_state (
  device_id  TEXT PRIMARY KEY,
  payload    TEXT NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE logs (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  device_id TEXT NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
  ts        INTEGER NOT NULL,
  line      TEXT NOT NULL
);
CREATE INDEX logs_device_ts ON logs(device_id, ts DESC);

-- 当前生效配置（scope = 'default' 或 deviceId）
CREATE TABLE configs (
  scope      TEXT PRIMARY KEY,
  revision   TEXT NOT NULL,
  json       TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  updated_by TEXT NOT NULL
);

-- 配置历史（回滚用）
CREATE TABLE config_revisions (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  scope      TEXT NOT NULL, revision TEXT NOT NULL,
  json       TEXT NOT NULL,
  created_at INTEGER NOT NULL, created_by TEXT NOT NULL
);
CREATE INDEX config_revisions_scope ON config_revisions(scope, created_at DESC);

-- 期望状态（启停）
CREATE TABLE desired (
  device_id TEXT PRIMARY KEY REFERENCES devices(id) ON DELETE CASCADE,
  running   INTEGER NOT NULL, rev INTEGER NOT NULL,
  at        INTEGER NOT NULL, by TEXT NOT NULL
);

-- 一次性指令通道（截图点播等）
CREATE TABLE commands (
  id           TEXT PRIMARY KEY,
  device_id    TEXT NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
  action       TEXT NOT NULL, payload TEXT,
  created_at   INTEGER NOT NULL, created_by TEXT NOT NULL,
  delivered_at INTEGER, acked_at INTEGER, result TEXT
);
CREATE INDEX commands_pending ON commands(device_id, delivered_at);

CREATE TABLE screenshots (
  id         TEXT PRIMARY KEY,
  device_id  TEXT NOT NULL REFERENCES devices(id) ON DELETE CASCADE,
  ts         INTEGER NOT NULL, path TEXT NOT NULL, bytes INTEGER NOT NULL,
  width      INTEGER, height INTEGER, label TEXT,
  created_at INTEGER NOT NULL
);
CREATE INDEX screenshots_device_ts ON screenshots(device_id, ts DESC);

CREATE TABLE sessions (
  token_hash   TEXT PRIMARY KEY,
  user         TEXT NOT NULL,
  created_at   INTEGER NOT NULL, expires_at INTEGER NOT NULL, last_seen_at INTEGER,
  ip           TEXT, user_agent TEXT
);

CREATE TABLE audit (
  id     INTEGER PRIMARY KEY AUTOINCREMENT,
  ts     INTEGER NOT NULL, actor TEXT NOT NULL, action TEXT NOT NULL,
  target TEXT, detail TEXT, ip TEXT
);
CREATE INDEX audit_ts ON audit(ts DESC);

-- 凭据与全局设置（panel_pass_hash 为 argon2id PHC 串）
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL, updated_at INTEGER NOT NULL);

CREATE TABLE schema_migrations (version INTEGER PRIMARY KEY, applied_at INTEGER NOT NULL);
```

`settings` 键：`panel_user`、`panel_pass_hash`、`device_token`、`default_report_interval_ms`、
`report_retention_days`（默认 30）、**`log_retention_days`（默认 7，日志单独算）**、
`screenshot_retention_n`（默认 10）、`screenshot_retention_days`（默认 30）。

**保留策略**：一个每日 ticker goroutine 清理过期 `reports` / `logs` / `screenshots`（含磁盘文件），
日志里打印清理条数。SQLite 定期 `PRAGMA optimize`，必要时 `VACUUM`（低频，避免长期膨胀）。

## 8. 前端设计

### 8.1 路由

| 路由 | 页面 | 阶段 |
|---|---|---|
| `/login` | 登录 | P0 |
| `/` | 设备总览（统计条 + 卡片网格 + 批量选择） | P1 |
| `/devices/:id` | 设备详情（实时状态、曲线、日志、截图、配置） | P1/P2 |
| `/configs` | 配置模板（默认 + 每设备覆盖 + 版本历史/回滚） | P1/P2 |
| `/audit` | 审计 | P2 |
| `/settings` | Token 显示/轮换、默认上报周期、保留策略 | P0/P2 |
| `/calibrate` | 标定页（**仅本地模式**可用，独立 app 见 D9） | P4 |

### 8.2 状态与实时

- TanStack Query，queryKey 约定：`['devices']`、`['device', id]`、`['device', id, 'logs', {limit,q}]`、`['config', scope]`、`['audit', filters]`。
- SSE `GET /api/v1/panel/events`：收到 `report` → `invalidateQueries(['devices'])` 与 `['device', id]`；`screenshot` → 失效截图列表。
- **SSE 断线兜底**：`EventSource` 的 `onerror` 触发后启用 5s 轮询；重连成功则停掉轮询。
- 倒计时沿用现有实现要点：**用设备上报的 `ts` 校正两端时钟偏差**，避免云手机与服务器时钟不一致导致进度条错乱。

### 8.3 卡片信息分层与「备注」的归属

总览卡片只回答两件事：**这台机器现在怎么样**、**我要立刻做什么**。所以：

- **留在卡片**：设备 ID、在线状态与最后上报、引擎状态徽章、BUFF 倒计时与进度条、轮次/输入方式/BUFF 开关概况
  （`●●○ 2/3` 而非三条 chip）、前台应用与门禁、**唯一需要立刻处理的告警**（配置未生效 / 最近错误）、四个操作按钮。
- **移到详情页**：机型 / Android / 版本、心跳（电量·温度·延迟）、协议版本、配置同步细节、上次结果、上报周期、历史与截图。
  卡片高度从「两段信息区 + 三条 chip + 两行脚注」压到 **210px**（E2E 里有 ≤300px 的回归断言）。
- **备注属于设备，不属于配置**：卡片与详情页都能编辑备注，但它写在**设备表**上（`PUT /api/v1/panel/devices/{id}`），
  不写进 config。理由是配置每次写入都会 bump `revision`，而设备只在 revision 变化时热重载 ——
  把备注塞进配置意味着「改一个字就让全部设备白重载一次配置」。协议层验收里专门有一项盯着这个不变量。
- 卡片上的「编辑」是**弹窗**：备注 + 自动补 BUFF 的三个开关一起改，保存时分别落到设备表与设备级配置。

### 8.4 视觉对齐

现有调色板（`#0d1014` 底 / `#141920` 卡片 / `#262d36` 边框 / `#7fd18b` 正常 / `#ffc53d` 警告 / `#ff6b6b` 异常 /
`#2563eb` 主色）搬进 `tokens.css` 的 Tailwind `@theme`，状态色语义（在线 / 掉线 / 挂机中 / 熔断）保持一一对应。
重构完成后用 `shots/` 的截图习惯做新旧对比，确认视觉无回退。

### 9.2 VPS 布局

|---|---|
| `/opt/altair/altaird` | 二进制（+ `altaird.bak` 上一版） |
| `/etc/systemd/system/altaird.service` | 服务单元（`User=altair`、`Restart=always`、数据目录写权限） |

  （**没有 `import`** —— D14 不迁移旧数据。）

### 9.3 迁移与一次性切换（D10：不分期，无灰度期）

> **不做数据迁移（D14）**：旧 `control-store.json` 里的设备与配置**不导入**。
> 上线后，默认配置与每台设备的覆盖（目标包名 / BUFF 键位与时长 / 输入方式）需要在**新面板重新录入一遍**。
> ⚠️ **切换前先把当前生效的配置抄成清单或截图**：`control-store.json` 是缩进 JSON，
> Python 停掉后用 `cat` 仍读得到，但**不会再有任何界面显示这些值**，只能手工翻文件对照 —— 别到那时才发现没记。

1. **本机验收**：`altaird fake-device --n 3 --interval 5s` 造流量，跑通登录 → 总览 → 启停 → 配置下发 → 截图 → 曲线。
2. **上线窗口**（硬切换，需一个明确的维护时段；执行人 = 实现者，需 SSH 方式，见 D15）：
   a. VPS 起 `altaird`（8788），Caddy 暂不切；
   b. 手动给 **1 台**云手机装带 v1 协议的新 APK，验证 report / config / 截图全通；
   c. **在新面板录入默认配置与每台设备的覆盖**，逐台核对包名与 BUFF 参数（对照切换前抄下的清单）；
   d. Caddy 切到新服务，停旧 Python；
   e. 全量 APK 升级；
   f. 验收通过后删除 Python 相关文件（§10）。
3. **回滚预案**：保留旧 `control-server.py` 与 `control-store.json` 备份到验收结束；
   Caddy 一行改回旧端口；APK 侧**服务器地址与协议版本都要在设置页可切**，回退不需要重装 APK。

### 9.4 不分期的风险与缓解 ⚠️

**风险**：窗口期内新旧不兼容。若 APK 铺开慢（云手机批量安装是人工操作），会出现
"设备能连上但协议不符"的**静默失败** —— 面板一片空白而服务器日志看着正常。

缓解手段（按推荐度）：

1. **建议保留 `--legacy-device-api` 开关（默认关）**：临时接受旧 `/api/report`、`/api/config`，
   让未升级的设备在灰度期也能被看见。约 40 行代码，是这套"不分期"方案里性价比最高的一张安全网。
   → **需要你确认是否采纳（见 §12.2 第一行）**
2. 上报里带 `protocolVersion`，面板直接标出每台设备的协议版本与"未升级"状态，升级进度一目了然。
3. 上线前先用假设备（`fake-device`）双协议回归，确保两条路径都通。

### 9.5 前置条件

- **Go 1.27.1 已装好**：在 `.toolchain/go`（工作区内，不碰 `/opt/homebrew` —— 那里写入被沙箱拦，且 brew 自身状态也不干净）。
  已写进 `tools/setup-toolchain.sh`（幂等、版本动态查询 + 阿里云镜像兜底）与 `.toolchain/env.sh`。
  ⚠️ **`GOPATH` / `GOMODCACHE` / `GOCACHE` 必须留在工作区内**：默认值落在 `~/go` 与 `~/Library/Caches/go-build`，
  受限环境下不可写，会让 `go build` 直接失败。已实测 `go build` 通过。
- 一个解析到 VPS 的域名（Caddy 自动证书）。
- **SSH 访问方式**（主机 / 用户 / 密钥路径）—— P4 部署前提供（D15）。
- APK 侧 `usesCleartextTraffic="true"` 保留不影响 HTTPS；切 HTTPS 后可考虑收紧为 network security config 白名单。

### 13.2.1 容量实测（回答"台数未知"这个开放问题）

用 `control/scripts/scale-check.sh` 与 `dbstat` 实测（不是估算）：

| 项 | 200 台设备、60s 上报周期 |
|---|---|
| `GET /api/v1/panel/devices`（N+1 共 ~1000 次查询） | **p50 19.6ms / max 20.7ms** |
| `POST /api/v1/device/report` | p50 1.1ms |
| 存储增量（改动前） | **1454 字节/份 → 399 MB/天 → 30 天 11.7 GB** ❌ |
| 存储增量（改动后） | **362 字节/份 → 99 MB/天（30 天 2.9 GB）+ 日志 7 天 0.4 GB** ✅ |

结论与动作：

- **N+1 查询不用优化**：200 台才 20ms，面板 5 秒轮询一次，占不到 0.5%。实测数据说话，不做无谓优化。
- **存储必须改**（已改）：`reports.payload` 把整包 JSON 每份都存一遍，而同一份内容每 60 秒重复一次。
  改成「时间序列只留标量 + `device_state` 每台一行保存最新快照」，**每份从 1454 降到 362 字节**。
  同时给日志单独一个保留期（默认 7 天）—— 设备一多，日志比曲线数据还占地方。
- **升级路径实测通过**：拿改动前生成的真实库（v1、260 行带 payload、20 台设备）跑迁移，
  `device_state` 正确搬入 20 行快照、时间序列 payload 清零、面板读回的引擎状态与心跳完整无损。

### 13.3 与计划的偏差（都是有意的）

| # | 计划 | 实际 | 为什么 |
|---|---|---|---|
| 1 | OpenAPI 双端 codegen（`oapi-codegen` + `openapi-typescript`） | **前端 codegen，Go 端手写 struct** | 本规模下 `oapi-codegen` 生成的 handler 接口只增加改动摩擦；契约一致性改由 CI 的 TS 生成检查 + 52 项冒烟验收兜住 |
| 2 | `--legacy-device-api` 待确认 | **已实现，默认关** | 硬切换失败时的唯一缓冲；实测旧端点可用且默认不生效 |
| 3 | `altaird show` 显示面板口令 | **只显示账号与设备 Token** | 口令只存 argon2id 哈希，系统里不存在明文，忘了只能 `set-password` 重设 —— 这是比旧版（明文入库 + 每 5 秒发给浏览器）严格得多的做法 |
| 4 | 前端产物拷进 `internal/webassets/dist` | **拷贝，但该目录除 `.gitkeep` 外不入库** | 避免把构建产物提交进仓库；缺产物时运行时给一条能自救的提示页，而不是裸 404 |
| 5 | 截图上传「通道待定」 | **root `screencap -p` + JPEG 压缩** | 复用 `Probe` 里已验证过的同一通道；PNG 转 JPEG(80)，超 2MB 自动降档重压 |
| 6 | （未提及） | **修掉老实现一个真实 bug** | 旧代码把 `desired.rev == 0`（服务端从未下发过）当成"下发停止"，导致新设备一启用集控就被强制停引擎。现在 `rev <= 0` 直接忽略 |
| 7 | （未提及） | **修掉一个自己刚写出来的安全漏洞** | 截图落盘用 `meta.deviceId` 直接拼路径，设备端可用 `"deviceId":"../../etc"` 写到数据目录之外；已收敛为安全目录名并加了验收项 |
| 8 | reports 保留原始 payload「便于追溯」 | **改为快照表 + 标量时间序列** | 实测每份 1454 字节、200 台 30 天 11.7GB，小 VPS 撑不住；完整内容只留最新一份（见 §13.2.1） |
| 9 | 日志保留期跟上报一致 | **日志单独 7 天，且可配** | 每份上报带若干行日志，200 台每天 230 万行，比时间序列还占地方 |
| 10 | （未提及） | **修掉一个配置 revision 撞号的 bug** | revision 只用毫秒生成，同一毫秒内连续两次写入会撞号 —— 而设备只在 revision 变化时热重载，撞号等于第二次改动被静默忽略。改成撞号自动加后缀，并加了「连写 50 次不重复」的回归测试（这个 bug 是被单测抓到的） |
| 11 | （未提及） | **部署脚本在写 Caddyfile 后必崩** | `install.sh` 里 `$DOMAIN）` 被 bash 当成变量名吞掉全角括号，`set -u` 下直接退出 —— 也就是装到一半停住、服务永远起不来。同类问题在 `preflight.sh` 里也有 2 处。写前置检查脚本时顺带扫出并全量修正 |
| 12 | （未提及） | **修掉一个 CLI 静默错库的 bug** | Go 的 `flag` 包遇到第一个位置参数就停止解析，`set-token 值 --db 路径` 里的 `--db` 被静默忽略、改动写到默认库上（看起来成功、实际改错库）；改为显式解析并加了 3 项验收 |

### 13.4 P4 还缺什么

| 缺的东西 | 影响 |
|---|---|
| **SSH 访问方式**（主机 / 用户 / 密钥） | 无法执行 `deploy/install.sh` 与切换；这是 P4 唯一的硬阻塞 |
| 域名已确定，但**实际域名值**未给 | `Caddyfile` 里的 `control.example.com` 需替换 |
| **云手机台数** | 只影响保留策略与分页调参，不阻塞部署 |
| 切换前排空动作 | 见 §9.3：抄录现有每台设备的 BUFF 参数（不迁移旧数据），并确认 `--legacy-device-api` 是否要在窗口期打开 |

> ⚠️ **发版顺序的硬约束**：APK 现在说的是 v1 协议，**旧 Python 服务端不认识**。
> 所以 `bash tools/release.sh 0.24.0` 发出新 APK **必须与新服务端上线配合**，
> 否则升级了 APK 的云手机会连不上（表现为集控静默失败）。
> 版本号不要手动改，交给 `release.sh`（它会改 `versionCode/versionName`、同步 `dist/`、打 tag、发 Release）。

> 另：`tools/control-server.py` 等旧文件的删除按 §10 放在**验收通过之后**执行，
> 它们是目前唯一能回滚的设备端实现。

**残余风险（如实记）**：交叉编译出的 `altaird-linux-amd64` 只验证到
「静态链接 ELF + 内嵌前端确实在包里 + 纯 Go SQLite 已编入 + 无动态依赖」，
**没有在 Linux 上实机跑过**（本机无容器运行时）。纯 Go 无 cgo 大幅降低了风险，
但首次部署时请把 `RUNBOOK.md` 第 3 步的 `/healthz` 探活当作真正的第一道验证。
