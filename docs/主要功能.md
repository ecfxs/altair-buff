# 主要功能与使用说明

本文依据 2026-09-26 的工作区源码整理，整理时版本元数据为 `0.28.6 / 52`（这批改动提交为 `0.29.0 / 53`）。功能描述不代表真机验收已完成，无障碍输入、覆盖升级等行为仍需实机确认。开发结构见 [软件整体架构](软件整体架构.md)，构建与分发见 [版本更新与发布](版本更新与发布.md)。

## 1. 软件用来做什么

阿尔泰在 Android 设备上，根据用户手动标记的位置，定时点击游戏技能，并可定时执行一次往返走位与跳跃。可选择 Root 或无障碍输入，技能和走位有各自的计时器，执行动作时按顺序串行完成。

| 功能 | 当前能力 |
|---|---|
| 定时补技能 / BUFF | 最多 4 个槽位，各自启用、各自配置周期 |
| 定时原地走位 | 左、右、左三段推杆；可关闭自动走位 |
| 可选跳跃 | 标记跳跃键后，在走位结束 1 秒后点一下 |
| 手动坐标标记 | 标记技能、轮盘中心、跳跃；保存后可重复使用 |
| 悬浮控制 | 悬浮球和面板、任务启停、标点回显、试走位、窗口复位 |
| 运行保护 | 目标前台检查、屏幕一致性检查、动作互斥、失败停止、未知触摸状态阻断 |
| 日志与状态 | 倒计时、运行计数、最近结果、日志复制/导出 |
| 软件更新 | 用户点击后从多个 HTTPS 源寻找更高版本，或指定地址/本地 APK |

当前版本不做技能图标识别、角色位置识别、自动进入自由市场、黑屏恢复、远程群控或后台自动升级。日志显示“输入已完成”只代表输入链路完成，不能证明技能实际生效；纯计时走位也不能保证精确回到原点。

## 2. 使用条件

- Android API 26（Android 8.0）及以上；主要目标是 Android 11/13 的 Root 云手机。最低版本声明不等于所有设备均已适配或实测。
- Root 模式要求 `su` 能取得 `uid=0`；无障碍模式要求用户在系统设置中开启「阿尔泰手势辅助」，不依赖 Root。普通手机安装更新需要系统确认。
- 允许“显示在其他应用上层”。任务依赖悬浮窗提供游戏中的停止入口，权限未开会拒绝启动。
- 目标游戏可正常进入前台，游戏按键布局与标记位置一致。标记与运行时保持相同分辨率、横竖屏和旋转方向。验收基线是**红手指 1280×720 横屏**；换到其它分辨率或方向时程序仍可运行，但必须重新标记并在游戏画面上用「回显」确认落点。
- 联网更新时能访问至少一个有效 HTTPS 更新源；技能与走位调度本身不依赖在线集控服务。

Root 输入使用系统注入接口，无障碍输入使用系统手势 API。实际兼容性取决于设备 ROM、服务生命周期及游戏对输入的处理；分屏、画中画、锁屏或前台不明确时，无障碍模式不开始新动作。设备验证范围见 [无障碍兼容与验收](无障碍兼容与验收.md)。

## 3. 第一次使用

1. 安装正式签名 APK，打开阿尔泰。在“设置 → 操作方式”选择 Root 或无障碍，再用“更多 → 检查输入”查看状态。默认 Root，老用户配置保持不变；无障碍需点“打开无障碍设置”手动启用服务后返回。
2. 在“设置 → 技能间隔”启用需要的技能并填写秒数。若需要走位，启用“原地走位”并配置参数；点击固定在设置页顶部的“保存设置”。
3. 点击“任务 → 打开悬浮窗去标记位置”或“更多 → 打开悬浮窗”。如果进入系统授权页，允许悬浮窗后返回，再点一次打开。
4. 切到实际游戏画面，点悬浮球展开面板，在“工具 → 选择当前游戏”记录目标包名。也可以在设置页直接填写正确包名；默认是 `com.nexon.mod`，不适用于所有游戏。
5. 在面板“标记位置”中，逐个点选要标记的项目，再点游戏画面上的对应位置。已启用至少一个技能或走位时，也可用“按顺序标记所需位置”完成必需项；跳跃需要单独标记。
6. 打开“工具 → 回显”，确认标点落在按键上。需要走位时，在任务停止状态下点“试走位一次”，观察方向、幅度及跳跃。
7. 在游戏前台点击悬浮面板“启动”。第一次立即执行已启用的动作；技能和走位同时到期时先补技能，再走位。之后按各自周期执行。

也可在主界面启动，但动作会等目标游戏回到前台才开始。设置页的“用当前前台应用标定”读取的是查询当时的前台；如果读到阿尔泰自己会拒绝标定，所以在游戏上使用悬浮面板“选择当前游戏”更直接。

## 4. 界面入口

| 入口 | 可执行操作 |
|---|---|
| 任务页 | 查看当前状态、最近结果、准备清单；跳转设置和打开悬浮窗 |
| 设置页 | 操作方式及无障碍设置入口；技能启用/周期、补 BUFF 间隔、走位开关及参数、目标游戏包名；保存设置 |
| 更多页 | 打开/关闭悬浮窗、查看/清空标记、检查输入、软件更新、本地文件选择、运行日志 |
| 底部常驻操作条 | 在任意页查看状态和倒计时，启动/停止任务；显示长操作名称及耗时 |
| 悬浮球 | 拖动位置、点开面板；通过状态色和倒计时快速看运行情况 |
| 悬浮面板 | 启停、已运行时间、标记位置、回显、走位开关、试走位、复位窗口、选择当前游戏 |
| 通知栏 | 停止自动任务 |

面板标题条可拖动，轻点可收回悬浮球。“复位窗口”调整悬浮窗位置，不会修正游戏角色位置，也不能替代“解除注入阻止”。

## 5. 技能与走位设置

### 5.1 参数表

以下是首次安装、没有旧配置时的默认值。已有用户优先沿用已保存配置和兼容迁移结果。

| 参数 | 默认值 | 可填写范围 / 单位 |
|---|---|---|
| 技能槽位 | 技能 1 开启，技能 2–4 关闭 | 最多 4 个，独立开关 |
| 各技能执行周期 | 280 | 1–86400 秒 |
| 补 BUFF 间隔 | 1500 | 100–10000 毫秒 |
| 原地走位 | 开启 | 开 / 关 |
| 走位执行间隔 | 15 | 1–1440 分钟 |
| 单程时长 D | 600 | 100–10000 毫秒 |
| 推杆幅度 | 6 | 1–30，单位为屏幕宽度百分比 |
| 跳跃按压 | 90 | 30–600 毫秒 |
| 普通技能按压 | 固定 90 毫秒 | 当前界面不开放调整 |
| 目标游戏 | `com.nexon.mod` | 实际应用包名 |

“技能执行周期”决定多久补一次该槽位，“补 BUFF 间隔”决定两个技能输入之间至少等多久，二者不能混淆。技能之间的等待太短，游戏可能还在播放动画而忽略下一次点击；此时应在确认标点正确后增加间隔。

### 5.2 排期与设置生效

每个技能从上次成功输入结束后重新计时。例如某槽位填写 280 秒，下次到期为本次输入完成后的 280 秒，不自动乘折扣系数。走位从上次整轮成功结束后按分钟计时。

动作不会并行。前台等待、动作执行和间隔都会影响实际发生时间，界面倒计时不是严格实时执行保证。回到游戏后执行已到期动作，不连续补放离开期间错过的所有轮次。

普通周期和补 BUFF 间隔保存后由引擎后续循环读取；改变走位总开关或目标游戏会停止任务，需要重新启动以校验条件。悬浮窗改变走位开关或目标游戏后，主界面会同步或提示草稿冲突；按提示确认当前值后再保存。

关闭走位后不要求标轮盘，只执行启用的技能；全部技能关闭且走位也关闭时没有可执行动作。关闭走位会保留原参数，之后可重新启用。

操作方式点选后立即保存。切换会先停止任务；若动作还在收尾、有更新或正在标记，等待完成后重新选择。两种方式共享坐标、配置和安全闸门，失败不会自动换通道。服务重连也不会自动恢复任务。

### 5.3 一轮走位

```text
向左推 D → 松手等 250ms → 向右推 2D → 松手等 250ms → 向左推 D → 松手
                                                                       ↓
                                                已标跳跃：等 1 秒 → 跳一下
                                                未标跳跃：本轮结束
```

默认 D=600ms，不跳跃时计划动作耗时 2900ms；加默认 90ms 跳跃后为 3990ms，另有系统执行开销。左右推杆端点距轮盘中心相同，幅度按屏宽计算；端点超屏会拒绝输入，需减小幅度或重标轮盘。

该动作通过时间近似抵消位移，碰撞、地形、卡顿、游戏动画等都可能使角色偏离原位置。“试走位一次”可在自动走位关闭时使用，但要求任务已停止、没有其他操作/标注，并已标记轮盘。它只测试走位，不补技能。

## 6. 坐标标记与持久保存

| 标记 | 何时必需 |
|---|---|
| 技能 1–4 | 对应槽位启用时 |
| 轮盘中心 | 自动走位开启时；手动试走位也需要 |
| 跳跃 | 可选；未标则走位后不跳 |

点击一个标记按钮只修改该项；长按技能按钮会从该槽位起，对后续启用技能及所需轮盘继续标记。全套顺序标记按当前启用配置生成，不会把跳跃自动列为必需项。先配置所需功能，再使用顺序标记。

采点层接收点击，采点点击不会作为游戏操作发送；可以用“取消标注”结束。连续标记中已完成的项目保留，取消不会回滚先前保存的点。开始重新标记会先停止任务并等动作收尾，标完后需人工重新启动。

坐标保存在本机应用配置中，同时记录标记时的屏幕宽、高与旋转方向。重新打开应用通常可继续使用；分辨率或旋转改变时需重标。游戏内部调整按键位置但屏幕尺寸未变，程序无法自动发现，需人工重标并用“回显”确认。回显只在目标游戏前台显示。

旧版本没有屏幕记录的坐标会按当前屏幕补记并写日志，不会仅因缺记录强制全量重标。已有明确记录但与当前屏幕不同，仍拒绝使用。旧 `v0.24` 配置中的技能和轮盘位置有迁移逻辑。

“更多 → 查看标记”将当前标记情况写入运行日志；“清空标记”需要确认，会停止任务并删除全部已保存标记。卸载或清除应用数据也会丢失配置，项目没有云端同步恢复功能。

## 7. 运行保护与停止

| 情况 | 软件行为 / 用户处理 |
|---|---|
| 目标游戏不在前台 | 等待阶段显示“等待游戏前台”；回到游戏后继续。输入中切走可能使本轮失败并触发停止，应读具体日志 |
| 缺少必需标记或屏幕记录不匹配 | 拒绝启动或执行，列出需要重新标记的项目 |
| 技能普通失败 | 按连续失败次数分别退避 30 秒、60 秒；同一槽位第 3 次失败停止 |
| 走位失败 | 停止任务，避免从未知位置自动重放往返 |
| 未确认松手 | 阻止后续自动和手动注入；停止按钮不会解除这一阻止 |
| 覆盖层让路或恢复失败 | 返回失败；窗口恢复未完成时拒绝继续输入 |
| 其他动作、更新或标注尚未完成 | 拒绝重复启动，等待收尾后再试 |

出现“未确认松手”时，先在游戏里确认角色不再持续移动、按键不再被按住，再点击主界面“任务 → 准备情况”的阻止说明，或悬浮面板对应状态行解除。若提示动作仍在收尾，等待结束再确认，然后手动启动。解除仅表示用户确认，程序没有识别触摸状态的闭环。

可从主界面、悬浮面板、通知栏停止；走位期间还提供注入区外的快捷停止按钮。停止会请求取消并尝试释放触摸，旧动作未完成收尾前不能重新启动。关闭悬浮窗也会停止任务；只离开主界面不等于停止。

短技能输入时，自有悬浮窗临时不可触摸但不移动。走位时，与输入范围重叠的窗口会临时缩小让路，再恢复原位，这是预期行为。Root 模式普通跳跃失败可只记录提示；无障碍模式的跳跃失败会停止本轮，避免掩盖服务断开。两种方式只要无法确认松手，都按危险失败处理。

前台检查是周期查询，不是零延迟保护；系统权限、窗口行为、Root 接口和游戏接受输入情况仍需在实际设备上验证。

## 8. 日志与软件更新

“更多 → 运行日志”支持复制、导出、清空。日志带 `HH:mm:ss` 时间戳，记录动作、失败原因和更新过程；导出为 `altair_log.txt`，保存位置由界面提示，优先为应用外部专属目录。日志平时在内存中且长度有限，重启前应导出需要保留的内容。

更新前先停止任务并等待操作完成：

1. 点“更多 → 软件更新 → 检查并更新”，程序依次尝试多个来源，只安装包名、签名正确且版本码更高的 APK。
2. 或填写 HTTPS APK 地址、设备本地 APK 完整路径，再点“用指定地址或本地文件更新”。无障碍模式建议使用“选择本地 APK 文件”，通过系统文件选择器授权读取。HTTP 地址被拒绝；所有来源均须通过包名、版本和签名检查。
3. Root 模式用后台脚本安装并尝试重开，约 5 秒只是预计时间。无障碍模式先保存校验后的 APK，再点“安装已验证更新”，按系统提示允许安装未知应用并确认安装；不会自动点击确认或保证重开。未安装文件可保留后重试，或用“丢弃待安装文件”清除。
4. 重开后点“更新日志”，确认安装结果及当前版本。自动任务不会随更新自行恢复，需要检查标记/设置后重新启动。

没有定时后台检查，也没有强制重装/降级的界面选项。下载失败或源只返回旧包时，不代表所有网络来源都已确认最新。维护者怎样发布新版本，见 [版本更新与发布](版本更新与发布.md)。

## 9. 常见排查

| 现象 | 优先检查 |
|---|---|
| 启动后一直等待 | 目标包名是否正确、游戏是否前台、所选模式是否就绪；无障碍模式还需检查分屏、画中画、系统弹窗和输入法 |
| 提示输入完成但技能没生效 | 回显标点是否准确、技能是否可用、补 BUFF 间隔是否足够；程序不会识别施法结果 |
| 角色往返后位置偏移 | 地形/碰撞、卡顿、单程时长及推杆幅度；该功能仅近似回位 |
| 显示屏幕已变化 | 恢复原屏幕方向/分辨率，或在实际游戏画面重标 |
| 面板暂时缩小 | 是否正在走位让路；结束后应恢复，持续异常时看让路恢复日志 |
| 试走位或启动被阻止 | 是否还有动作收尾、长操作、标注，或未确认松手闸门未解除 |
| 更新包签名不匹配 | 是否装了 debug 包、其他签名包，或下载源错误；不能靠重复点击覆盖解决 |
| 更新后配置或运行状态不符 | 确认是否覆盖安装还是卸载重装；配置可保留，运行计时与任务不会自动恢复 |
