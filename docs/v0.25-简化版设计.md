## 1. 这一版做了什么

从 v0.24.14 的「什么都想做」收敛成**只做两件事**的工具：

| | v0.24 | v0.25 |
|---|---|---|
| 计时 | 单一周期（最短 BUFF 时长 × 0.94），走位只在首轮 | **两套独立计时**：BUFF 每槽位各自计时；走位独立 15 分钟计时 |
| 坐标来源 | 内置实测值 + 技能带 74px 自动吸附 + 血条定位 | **全部手动标注**，落盘后永久沿用 |
| 输入通道 | 键盘/触摸二选一 | 只有触摸（键盘通道整体删除） |
| 走位 | 左 600ms → 右 600ms | 左 D → 右 2D → 左 D → **跳一下** |
| 集控 | 设备上报 / 群控台下发 / 截图上传 | **整体下线**（APK 页 + Go 服务端 + React 面板 + 部署脚本） |
| 场景识别 | 菜单/自由市场/传送点/出口对齐/血条/亮度/黑屏 | **全部删除** |
| 页面 | 运行 / 设置 / 集控 / 日志 | 运行 / 设置 / 更新 / 日志 |

**保留不变的**：自动更新（多源容灾）、原地走位、前台门禁、失败熔断、悬浮窗、日志页。

## 2. 功能规格

### 2.1 两套独立计时器

```
启动任务 ──┬── BUFF 槽位 1..4：各自 dueAt = 上次成功 + 时长 × 0.94
           └── 走位：walkDueAt = 上次走完 + 间隔（默认 15 分钟）
```

- **启动时两者都立即执行一次**（用户要求：点完启动马上能看到动作，而不是干等 15 分钟）。
- 启动那一刻两者同时到点，实际顺序是**先补 BUFF、再走位** —— 补 BUFF 是主功能，
  先把它做掉；即使随后走位出问题，BUFF 也已经补上了。
- 为什么 ×0.94：留 6% 余量吸收抖动与卡顿。**每槽位独立**，所以 280 秒的 BUFF 和 600 秒的 BUFF
  互不干扰（统一按最短时长补会把长 BUFF 过量重放）。

### 2.2 坐标标注（`Picks`）

| 槽位 | 用途 | 缺了会怎样 |
|---|---|---|
| 技能1..技能4 | 补 BUFF 时依次点 | **拒绝启动**（宁可启动时明确拒绝，也不要每轮静默失败） |
| 跳跃 | 走位结尾点一下 | 走位照走，但不跳（界面与日志都会提示） |
| 轮盘中心 | 推杆原点 | 用默认左下角位置兜底，界面标注「未标注」 |

- 交互：悬浮窗上「标技能N」→ 点画面上那个位置 → 自动保存。**每个槽位独立保存**，
  改一个不会动到其它项。
- 存储：SharedPreferences `picks`，值形如 `"0.74160,0.56730"`（归一化 0~1）。
  用文本是为了 `adb shell` 里能直接看懂、能手工改。
- 迁移：v0.24 的坐标（`overlay/pickedPoints` 前 4 项、`market/joyCxMilli,joyCyMilli`）
  首次读取时自动搬过来，老用户不必重标。
- 回显：悬浮窗「回显:开」把标注点画在游戏画面上（只在目标游戏前台时显示）。

### 2.3 原地走位（`WalkFlow`）

```
① 轮盘左推 D 毫秒
② 轮盘右推 2D 毫秒      ← 双倍：越过原点再往右
③ 轮盘左推 D 毫秒        ← 回到原点
④ 原地跳一下
```

- D 默认 600ms，设置页可调；推杆幅度默认屏宽 6%。
- **纯时长驱动，不截任何图**：曾经用血条 x 闭环回原点，但每步截图与按键抢同一个常驻
  root shell（实机把按键堵成 6 秒一次）。1:2:1 的配比本身就保证回到起点附近。
- 通道用 `joystickWalk` 默认的 `input motionevent`（按下 → 拖到偏移 → 保持 → 松手），
  该机型不支持时自动退回 `input swipe`。

### 2.4 安全约束

1. **前台门禁**：只有 `targetPkg` 在前台才动手；不是则记日志、30 秒后再看（不算失败）。
2. **失败熔断**：同一槽位连续失败 3 次 → 停止等人工，绝不死循环猛点。
   单次失败按 30s × 连续次数退避重试。

### 2.5 覆盖层在注入时必须「让路」（`InjectShield`）

`input` 注入的触摸由系统按 **z 序**交给最上面那个**可触摸**窗口 —— 悬浮面板/球就浮在游戏之上，
所以只要它盖住了轮盘中心或技能键的位置，注入的 DOWN/MOVE/UP 就全打在**面板自己的按钮**上。

实机现象（用户报告）：展开「工具」后面板变高、正好盖住左下角轮盘，此时点「试走位一次」，
注入的第一个 DOWN 落在面板下部的「复位窗口位置」上 —— 面板当场收起成球，
看起来就是**「一点试走位，悬浮窗自己消失了」**，而角色一步没动。

所以**任何注入前后都要把覆盖层切成 `FLAG_NOT_TOUCHABLE`**：

- `Probe.tapNorm` / `Probe.joystickWalk` 统一用 `InjectShield.withPassThrough { … }` 包住注入命令；
- `OverlayService` 在 `onCreate/onDestroy` 注册让路实现，同步改窗口参数
  （必须同步：闸门没关好就把注入发出去 = 没做；用计数支持两条线程同时注入）；
- 采点层一起切 —— 否则任务运行中用户正在标注，引擎的注入点击会被采点层吃掉并
  **静默存下一个错坐标**（正是本项目最忌讳的失败模式）。

## 3. 代码结构

```
probe/src/main/java/com/altair/probe/
  MainActivity.kt     四页签：运行 / 设置 / 更新 / 日志
  OverlayService.kt   悬浮窗：启停 + 逐项标注 + 标点回显 + 试走位
  PickView.kt         全屏标注层（点一下采一个点，自带「完成标注」）
  MarksView           标点回显层（只画标注点，同文件内）
  Engine.kt           两套计时器 + 门禁 + 熔断
  WalkFlow.kt         1:2:1 走位 + 跳
  Picks.kt            标注点仓库（唯一坐标来源 + 旧数据迁移）
  Probe.kt            底层通道：触摸（点击/摇杆）、前台包名、root、截图
  Updater.kt          多源自更新
  RootShell.kt        常驻 root shell（Activity 与悬浮窗共用一个 su 进程）
  ShellCore.kt        全局单例（probe / updater / root）
  LogBus.kt / Busy.kt 日志总线 / 操作互斥状态条
```

**零第三方依赖**：并发用 `Thread`，UI 用系统 `Activity`，不引 coroutines / appcompat / core-ktx。

## 4. 构建与发布

```bash
bash tools/setup-toolchain.sh          # 首次：装工作区内 JDK17 / SDK / Gradle
bash tools/build.sh                    # debug + release APK
bash tools/release.sh 0.25.0           # 改版本号 → 构建 → GitHub Release → 同步 dist/
```

- 签名用工作区内的 `keystore/probe.jks`（不依赖 `~/.android`）。
- 自动更新固定地址：`https://github.com/ecfxs/altair-buff/releases/latest/download/probe-release.apk`
  （APK 内按 gh-proxy → ghfast → GitHub → jsDelivr 顺序容灾切换）。

## 5. 调参入口一览

| 想改什么 | 在哪改 |
|---|---|
| 补 BUFF 的槽位与时长 | 设置页「BUFF 技能」（每槽位独立，秒） |
| 走位单程时长 D | 设置页「原地走位」 |
| 走位间隔（默认 15 分钟） | 同上 |
| 推杆幅度 | 同上（走得太少调大，走过头调小） |
| 跳跃按压时长 | 同上（默认 90ms） |
| 目标游戏门禁 | 设置页「门禁 · 目标游戏」 |
| 按压参数（90ms / swipe） | 代码常量 `Picks.TAP_PRESS_MS` / `TAP_METHOD`（**刻意不开放界面**：多档切换是"悬浮窗生效、引擎无效"这类 bug 的温床） |
