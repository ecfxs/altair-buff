# P0 探测 APK — 安装与使用说明

## 这是什么

P0 是**开工前的最后一次实测**。设计文档里所有能问的都问完了、能从截图挖的都挖完了，
只剩三项**必须装到红手指上跑一次才知道**的东西：

| 编号 | 待测项 | 为什么必须实测 |
|---|---|---|
| R1 | **root 真伪与权限范围** | 平台有开关 ≠ `su` 真能提权。部分红手指实例的 `su` 是阉割版 |
| R2 | **`screencap` 是否黑屏 / 真实 displayId** | 虚拟显示环境下这是头号故障，必须先自检 |
| R3 | **截图与按键的往返时延** | 直接决定采样率上限和走位步长参数 |

这个 APK 就是去测这三样，并把结果整理成一段**可以直接复制回 PC** 的报告。

**它不会修改任何东西**，除了在自己 cache 目录里存几张临时截图。
（唯一有副作用的按钮是「发送数字键1 / 方向键右」，那是给你人工验证游戏响应用的。）

## 一、装进红手指

红手指的安装方式通常有这几种，任选其一：

### 方式 A：文件上传（最常用）
1. 打开红手指客户端 → 进入你的云手机
2. 找到「上传文件」/「文件管理」/「APK 安装」入口
3. 上传这个文件：
   ```
   probe/build/outputs/apk/release/probe-release.apk
   ```
4. 上传后在云手机内点它安装（若提示「未知来源」，去设置里允许即可）

### 方式 B：直接在云手机里下载
把 APK 放到任意可公开访问的地址（网盘直链、对象存储、你的服务器），
在云手机浏览器里打开下载安装。

### 方式 C：平台推送安装
部分红手指型号支持控制台直接拖入 APK 推送安装。

> **注意**：APK 用的是 debug 签名，安装时若提示「已存在同包名应用」，
> 先卸载旧版（包名 `com.altair.probe`）再装。

## 二、开始探测

### 准备工作（重要）

**先把游戏切到前台，停在能看清画面的位置。**
理由是探测要验证的正是「能不能截到游戏画面」。如果探测时停在桌面，
截到的是桌面而不是游戏，结论就没意义了。

推荐停在**野外地图**（有血条、有 BUFF 技能键的那个场景）。

### 操作顺序

> **关键概念：④⑤⑥ 三个按钮都是「延迟执行」。**
> 探针的按钮在游戏里点不到（点的时候探针在前台，按键只会发给探针自己）。
> 所以这三个按钮的正确用法是：**点完立刻切到游戏**，到点后探针在后台自动执行。
> 执行期间会重复多次，你不必卡时间点，安心看着就行。

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 打开 **P0探测** App | 图标名「P0探测」 |
| 2 | 点 **① 开始探测** | 约 30~60 秒，期间反复截图，游戏会短暂卡顿，**属正常** |
| 3 | 点 **② 连续截图 5s** | 测持续采样率 |
| 4 | 点 **③ 采集压测** | 对比 PNG / RAW 两种截图通道的时延 |
| 5 | 点 **④ 游戏中截图(10s)** → **立刻切到游戏** | 10 秒后自动截图。**这是验证"游戏画面能截到"的唯一方法** |
| 6 | 切回 App 看 ④ 结果 → 点 **⑤ 游戏中按键测试** → **立刻切到游戏** | 10 秒后自动发【数字键1】共 5 次、间隔 3 秒。**看技能有没有放出来** |
| 7 | 切回来 → 点 **⑥ 游戏中走位测试** → **立刻切到游戏** | 10 秒后自动连发方向键（右 15 次 → 左 15 次）× 3 轮。**看角色有没有来回走** |
| 8 | 切回 App，点 **复制报告** | 复制到剪贴板 |
| 9 | 用红手指的剪贴板同步把文本带回 PC | 或用「分享/导出」发到微信/QQ |

> **如果第 6/7 步游戏毫无反应**：先别下结论。告诉我是「完全没动」还是「动了一下就停」，
> 这两种对应完全不同的原因（焦点问题 vs 连发频率不够），我会据此调整。

> **如果第 5 步显示「★ 判定为黑屏」**：说明游戏画面被 `FLAG_SECURE` 保护，
> 截屏通道拿不到游戏画面。这是重要发现，请务必告诉我——架构需要改走 MediaProjection。

## 三、自更新（装一次，以后不用再手动装）

从 **v0.4** 起，App 内置了自更新。

### 原理

| 环节 | 正常 App 的障碍 | 我们的解法 |
|---|---|---|
| 安装 APK | 系统强制弹确认框 | **root 下 `pm install -r` 绕过确认**（已实测 uid=0 + 满 Capabilities） |
| 安装会杀进程 | 装到一半脚本随进程死掉 | 安装脚本用 `setsid` **脱离进程组**，装完自己 `am start` 重启 |
| 版本判断 | 需要额外的版本清单 | 直接读 **APK 自身的 versionCode**，不用清单文件 |

### 怎么用

App 里已经**内置了默认更新源**，你什么都不用填：

```
https://github.com/ecfxs/altair-buff/releases/latest/download/probe-release.apk
```

点 **「自更新」** 即可。流程是：检查版本 → 下载 → 静默安装 → 自动重启 →
重启后自动显示「上次自更新结果」（来自 `/data/local/tmp/altair_update.log`）。

**「启动自动检查更新」默认开启**：以后每次打开 App 会自动查一次，有新版本就装上。

### ⚠️ 一个必须知道的坑（已修）

GitHub 的 `/releases/latest/download/` 重定向**会被 CDN 按 URL 缓存**。
实测刚发完新版直接请求会拿到**上一个版本**的 APK ——
对自更新来说是致命的：会「下载到旧包 → 版本不更高 → 提示已是最新 → **静默地永远不更新**」。

已在代码里加**缓存破坏参数**（每次请求带不同时间戳）修掉。
这个失败模式是安全的（只是不更新，不会装错东西），但会让人困惑。

### 如果 GitHub 下载太慢或不通

实测从开发机拉取只有 16~96 KB/s。**云手机在国内机房，可能更慢甚至不通**。

兜底方案（App 里已实现）：

1. 用红手指的**「上传文件」**把 `probe-release.apk` 传到云手机（例如 `/sdcard/Download/`）
2. 在 App 的输入框里填那个路径，点 **「安装本地APK」**
3. App 用 root 直接装 —— **省掉系统安装器的所有确认步骤**，比手动装快得多

> 如果实测发现 GitHub 确实不通，我会把更新源换成国内可达的托管
> （jsDelivr / 对象存储 / Gitee），告诉我即可。

## 三之二、悬浮控制台（推荐先用这个）★

**把测试按钮浮在游戏画面之上**，不用再「点完立刻切到游戏」猜时间。

### 怎么开

在 App 里点 **「启动悬浮窗 ★」**。悬浮窗权限正常需要你去系统设置里手动开，
但我们是 root —— App 会**用 `appops set` 自己授权**，你什么都不用操作。

### 悬浮窗上有什么

| 按钮 | 作用 |
|---|---|
| **截图** | 立刻截一帧，报告分辨率/横竖屏/方差/熵/是否黑屏 + **当前焦点窗口** |
| **数字键1** | 立刻发 KeyEvent 8（游戏若响应就会放技能） |
| **方向→ / ←** | 立刻发方向键，直接看角色动不动 |
| **按键诊断** | 依次发 数字键1×3 → 返回键 → Home键，并报告结论 |
| **触摸×4** | 在右侧技能键排 4 个估计位置依次点击 |
| **ROI显示** ★ | **把识别框直接画在游戏画面上**（见下） |
| **复制日志** | 一键复制全部日志 |
| **隐藏** | 收起面板（服务和 ROI 层仍在） |

面板可**拖动**（按住标题栏拖）。它是 `FLAG_NOT_FOCUSABLE` 的，
**不会抢走游戏的输入焦点** —— 这点很关键，否则悬浮窗自己就会让按键失效。

### ROI 显示（这个是质变）

点 **「ROI显示」** 后，游戏画面上会叠一层标记：

| 颜色 | 含义 |
|---|---|
| 🟢 绿框 | **小地图** `[0.0023, 0.1097, 0.1477, 0.2958]` |
| 🔴 红框 | **HUD 血条** `[0.4289, 0.8958, 0.5711, 0.9125]` |
| 🟡 黄框+4个圆 | **技能键排**（估计位置，待验证） |
| 🔵 青十字 | 屏幕中心 |
| 细白线 | 1/10 归一化网格（用来读坐标） |

**框对不对，一眼就能看出来。** 这比反复截图→分析→打印坐标高效太多，
后续所有标定都靠它。

## 三之三、坐标采集（采点）★

键盘通道若走不通，就只能改用**触摸点击**，而触摸必须知道按钮的准确坐标。
从截图推算不准（技能键是半透明圆角，自动检测效果很差），所以直接让你点。

### 怎么用

1. 悬浮窗上点 **「★采点」** → 铺一层全屏透明覆盖层（你能看见游戏画面）
2. **直接在游戏画面上依次点技能键 1、2、3、4 的位置**
3. 每点一下会留下一个**带编号的黄色标记**，日志同步记录坐标
4. 再点 **「★采点」** 关闭 → 日志打印全部坐标，例如：

```
采点模式：已关闭，共 4 个点
点1 = [0.7482, 0.5833]
点2 = [0.7896, 0.5833]
点3 = [0.8310, 0.5833]
点4 = [0.8724, 0.5833]
```

5. 点 **「点1」「点2」「点3」「点4」** → 按采集到的坐标执行 `input tap`

**采点期间游戏收不到点击** —— 这是故意的，采点不该产生任何副作用。

### 为什么这一步很关键

它一次性解决了「坐标从哪来」这个一直卡着的问题：**不用推算、不用标定工具、
不用模板匹配，你点一下就是准确值**。而且采到的坐标可以直接用到最终版里。

> 注意：坐标是**归一化**的（0~1），所以换分辨率也不用重采。

## 四、报告怎么看

报告分 7 段。你只需要重点看这 4 行：

```
======== 1. root 探测 ========
常驻 shell 建立     成功 (XXXms)
常驻 shell 单次往返  XXms

======== 3. 显示枚举 ========
display 1            XXms  XXXXXB  OK  1280x720  方差=XX.XX  熵=X.XX  有内容

======== 4. 截图黑屏自检与时延 ========
时延 min/中位/p90/max   XX/XX/XX/XX ms
黑屏判定            正常，画面有内容 ✅

======== 7. 结论与建议 ========
（这里是自动生成的结论，直接看它就行）
```

### 结果对应的分支

| 结果 | 含义 | 后续 |
|---|---|---|
| `常驻 shell 建立 成功` | root 可用 ✅ | 走设计文档的主通道，性能最好 |
| `常驻 shell 建立 失败` | root 没开或不可用 | 去红手指客户端打开 root 开关重测；实在不行降级无障碍通道（能用但慢 3~5 倍） |
| 某个 `display N` 显示 `有内容` | 找到游戏所在显示 ✅ | 记下这个 N，写进配置 |
| 全部显示 `★黑屏/纯色` | screencap 截不到画面 ⚠ | 必须走 MediaProjection 兜底通道，架构要调整 |
| 截图中位时延 < 100ms | 采样率充裕 | 走位可做 5Hz 闭环 |
| 截图中位时延 100~250ms | 够用 | 走位降到 3Hz，步长放长 |
| 截图中位时延 > 600ms | 偏紧 | 走位只能开环估计（定时长盲走） |

## 六、附：构建与发布（开发者用）

```bash
# 一次性：安装工作区内的工具链（JDK17 + Gradle 8.2 + Android SDK）
bash tools/setup-toolchain.sh

# 构建
bash tools/build.sh              # debug + release
bash tools/build.sh clean        # 清理
```

工具链全部在 `.toolchain/` 内（约 600MB），不写系统目录。
